# Учёт проекта «ТАУ-4»

Источник правды — `docs/tracker/tracker.yaml`. Excel `ТАУ-4_график.xlsx` из него генерируется
скриптом `tools/tracker.py`. Excel и YAML пишет только оркестратор.

Нужен Python 3 с `openpyxl` и `PyYAML` (`pip install -r tools/requirements.txt`). Команды — из корня репозитория.

## Команды

```
python tools/tracker.py build                       # собрать Excel из YAML (атомарно)
python tools/tracker.py sync                        # прочитать заметки из Excel в YAML, затем build
python tools/tracker.py add --id 1.9 --title "Название" --parent 1 --owner "Sonnet medium" \
       --review "Sonnet medium" --start 2026-11-10 --end 2026-11-14
python tools/tracker.py add --id 3.7 --title "Без --parent: родитель 3 берётся из номера"
python tools/tracker.py mark 0.5 1 Выполнено        # пункт, неделя, статус
python tools/tracker.py mark 2.1 2026-11-12 "В работе"   # неделя — любой датой внутри неё
python tools/tracker.py mark 5.3 8-10 План          # диапазон недель; статус «-» убирает факт
python tools/tracker.py log --item 0.5 --what "Готов tracker.py" --who "Sonnet 5.5 / medium" \
       --commit abc1234 --rounds 1 --tokens 120000 --link https://...
python tools/tracker.py review --item 0.5 --round 1 --severity существенное \
       --text "Суть" --repro "Как воспроизвести" --by "Sonnet 5.5 / high"
python tools/tracker.py review-status R-0.5-1 исправлено --comment "Исправлено в abc1234"
python tools/tracker.py decision Р-0 --answer "Название принято"
python tools/tracker.py parity add --id P-SCH-001 --area "Схема" --what "Точка h берёт y+z" \
       --source 1.1 --delphi "..." --fr FR-12 --substage 1.1 --test "tests/..."
python tools/tracker.py parity set P-SCH-001 проверено --test "tests/..."
```

Статусы: «План», «В работе», «Выполнено», «Доработка», «Ждёт решения».
Серьёзность замечаний: блокирующее, существенное, незначительное, предложение.
Статусы замечаний: открыто, исправлено, отложено, отклонено.
Состояния паритета: не начато, сделано, проверено. Источник паритета: `1.1` или `К2`.

Общие опции: `--yaml ПУТЬ` и `--out ПУТЬ` (или переменные `TRACKER_YAML`, `TRACKER_XLSX`) — работать
с другими файлами, например для проб. Команды, меняющие YAML, сразу пересобирают Excel;
`--no-build` — только записать YAML. Коды выхода: 0 — успех, 1 — ошибка данных или аргументов,
2 — Excel-файл занят.

## Как это работает

- **Клетка недели:** есть факт — он; иначе неделя внутри плана — «План»; иначе пусто
  (недели праздников и сессии подсвечены; календарь — в `tracker.yaml`, раздел `calendar`).
- **Строка этапа** показывает статус подэтапов: «Ждёт решения» > «Доработка» > «В работе» >
  «Выполнено» (когда все активные подэтапы недели выполнены) > «План». Сроки этапа — из подэтапов.
- Сетка недель сама растёт, если план или факт выходят за апрель 2027.
- **Развилки** лежат на листе «Решения» отдельными строками Р-0…Р-9 (как в `docs/DECISIONS.md`);
  внутри графика развилка — часть подэтапа (например, Р-2 и Р-3 в 2.5, Р-5 в 4.7).
- **Заметки пользователя:** пишите в колонку «Комментарий» листа «График» и в колонки
  «Решение пользователя» / «Дата решения» листа «Решения».
  - Перед **любой** записью Excel (build и все команды, меняющие YAML) скрипт сам считывает эти ячейки
    в YAML (sync). Заметка не потеряется, даже если забыть запустить `sync`.
  - Чтобы отличить правку пользователя от устаревшего текста, в Excel лежит скрытый лист `_snapshot`
    (то, что скрипт записал в эти ячейки). В YAML попадает только то, что вы изменили в Excel.
    Правка в YAML, сделанная после сборки, не затирается старым текстом из Excel.
  - Если одну заметку изменили и в YAML, и в Excel, сохраняются обе: `текст YAML | Excel: текст Excel`,
    выводится предупреждение.
  - Очистка ячейки в Excel стирает заметку в YAML. Если ответ на развилку изменён, а дата нет,
    ставится сегодняшняя дата.
  - Если sync не удался (файл повреждён), Excel не перезаписывается.
- **Файл занят:** если Excel открыт (есть `~$…`) или файл держит OneDrive, Excel не перезаписывается,
  команда печатает сообщение и завершается кодом 2. Изменения команд `add/mark/log/…` при этом уже
  записаны в YAML; закройте файл и запустите `build`.
- Строки, добавленные в Excel вручную, при пересборке исчезают (sync предупредит); новые пункты — командой `add`.
  Остальные правки листов тоже теряются — правьте YAML.
- Комментарии внутри данных YAML командами не сохраняются (заголовок файла и неизвестные ключи верхнего
  уровня сохраняются); заметки пишите в поле `comment`.
- Статус «Выполнено» — решение оркестратора; в «Легенде» это «принято после ревью». Подэтапы,
  выполненные до формального ревью (например, 0.1), отмечены по указанию оркестратора.
- Печать: «График» — A3 альбом, 1 страница в ширину; остальные листы — A4 альбом, заголовок повторяется.

Листы Excel: «График», «Сроки», «История», «Ревью», «Решения», «Паритет», «Легенда» (и скрытый `_snapshot`).
Формат YAML описан комментариями в начале `tracker.yaml`.
