## Что сделать
1. По каждой работе, где студент пользуется CONTROL, записать один или несколько UC. Номера — `UC-<NN>`.
2. **Блок UC:**
   - **Название и цель** — что студент должен получить.
   - **Источник** — методичка (часть, ЛР, страница или раздел, если они есть в выдержке) и скилл.
   - **Исходные данные** — пример из методички или из `samples.md`. Для работ «под любые T1, T2, T3» взять один вариант и указать допустимый диапазон параметров.
   - **Шаги** — по поведению, а не по окнам Delphi: «собрать схему: W — апериодическое звено K, T…», «построить ЛАЧХ на диапазоне…», «поставить курсор на ω = …». Окна и пункты меню 1.1 давать в скобках для узнаваемости.
   - **Ожидаемый результат** — числа, которые студент записывает в отчёт: Kкр, ωкр, запасы, перерегулирование, tр, амплитуда и частота автоколебаний и т. п. Числа вычисли сам по формуле из методички или из аналитической части скилла (Python, numpy/scipy). Дай 4–5 значащих цифр и формулу. Эти значения потом проверит оракул mpmath (1.5).
   - **Проверяемые требования** — список FR, которые сценарий задействует.
   - **Что фиксирует снимок** — какие диаграммы или таблицы студент вставляет в отчёт.
3. **Шум измерений.** Скиллы tau-lab-* генерируют правдоподобные «измерения» с погрешностью отсчёта. В ожидаемые значения шум не берём: только точные расчётные числа.
4. **Покрытие.** В конце файла:
   - таблица «UC → FR»;
   - список областей FR, которые не задействует ни один UC;
   - чего не хватает в FR для сценариев (раздел «Замечания к FR»).
5. **Открытые вопросы** — `ОВ-UC-<n>`: что нельзя установить без методички целиком или без запуска программы.
