## Что проверено и в порядке

### 1. Тесты tracker.py
- **Недели и даты** (прямой вызов функций): неделя 1 = 02.11.2026; неделя 5 «Нояб-Дек 30-6»; **неделя 9 = 28.12–03.01, «Дек-Янв 28-3»**; 10 = 04.01; 26 = 26.04–02.05 «Апр-Май 26-2»; 31 = «Май-Июн 31-6». Високосный год: 29.02.2028 → неделя 70, 01.03.2027 → 18. Дата до начала даёт 0 и понятную ошибку в `mark`.
- **Расширение сетки.** `mark 0.2 60 Выполнено` → колонки до BJ, комментарий в BK; слияния `C1:BJ1`, `C2:K2`, `L2:BJ2`, `A1:A5`, `B1:B5`, `BK1:BK5`. План в 2028 (`add … 2028-01-03/2028-02-29`) даёт блоки 2026, 2027 и 2028 (`L2:BK2`, `BL2:BT2`), слияния верны.
- **Круговой обмен YAML.** `mark` без изменений даёт файл, идентичный исходному (diff пуст), заголовок сохраняется.
- **Sync, заметки.** Переводы строк, кавычки, двоеточия, `#`, `{a: b}`, обратная косая, U+2028, эмодзи, кириллица проходят Excel → YAML → Excel без искажений (в том числе набор через Excel COM). Сопоставление идёт по № в колонке A, колонка заметок ищется по заголовку «Комментарий» в строках 1–5; вставка строки или колонки в Excel сдвиг не ломает. Пустая ячейка = «без изменений», «-» стирает. Числа и даты в заметках обсуждены в R-0.5-9.
- **Sync, решения.** Ответ, ввод даты датой Excel, подстановка сегодняшней даты при пустой; ответ «-» сбрасывает дату.
- **Замок.** Файл `~$…` рядом: `build` и `mark` → код 2, xlsx не менялся (md5 прежний), временных файлов нет. Файл, открытый с запретом записи (`FileShare.Read`), → «занят», код 2, ничего не записано. С настоящим Excel (COM): `~$x.xlsx` появился, `build` вернул 2. `sync` при открытом Excel читает сохранённые данные с предупреждением.
- **Запись.** xlsx пишется во временный файл рядом и подменяется `os.replace`; при ошибке временный файл удаляется. YAML пишется так же.
- **Коды выхода:** 0 успех, 1 ошибка данных или аргументов, 2 занят файл. Консоль Windows (кодовая страница 65001, `reconfigure(utf-8)`) выводит кириллицу без искажений.
- **CLI-проверки:** неверный статус, неверный номер пункта, неделя 0, неделя до начала сетки, `review-status` в любом регистре, `add` без пары `--start/--end`, дубль номера, несовпадающий префикс при `--parent` → понятные сообщения, код 1. Вставка нового подэтапа идёт после последнего потомка родителя.
