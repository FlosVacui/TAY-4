# Функциональные требования: расчёты и окна исследования

Файл исполнителя Б подэтапа 1.1. Области `RTH`, `ROO`, `FRQ`, `PRC`, `MIN`, `ANL`, `QLT`. Нефункциональные требования здесь не повторяются: они в [SRS](../SRS.md), раздел 4. Термины — в [глоссарии](../../glossary.md).

## Как читать

- Заметки разбора оригинала: `notes/` — это `work/control/notes/` рядом с папкой `TAY-4`.
- Ссылки на Delphi — файл и строка в `CONTROL_src` по метке `v2-delphi-final`. Исходники после метки не менялись, только документы.
- Источник `1.1` — поведение есть в CONTROL 1.1 (и потому в CONTROL 2). Источник `К2` — только в CONTROL 2.
- Подэтапы: расчёт — 5.x, окно и поведение интерфейса — 6.x. Расчётные подэтапы: 5.2 — модель системы и «Параметры счета», 5.3 — Раус и D-разбиение, 5.4 — корни и годографы, 5.5 — частотные, 5.6 — процесс и его производные виды анализа, 5.7 — поиск минимума, 5.8 — показатели. Окна: 6.3 — компонент диаграмм, 6.4 — окна исследования и таблицы.
- Режим совместимости 1.1 (ROADMAP, раздел 3) повторяет методы 1.1: Бэрстоу, Паде 2/4, РК4 с постоянным шагом, абсолютный порог Рауса. Где метод 1.1 и метод CONTROL 2 различаются, пишутся две FR.
- «Причуда → 1.7» — поведение оригинала, похожее на ошибку. Здесь оно только описано. Решает подэтап 1.7 (развилка Р-1).
- Расчётные величины сравниваются с допусками из `docs/testing/tolerances.md` (1.3). Разрывные результаты (клетки Рауса, число правых корней, моменты переключения реле) сравниваются по правилам 1.3.
- Правила сведения (исполнитель Г): FR, снятая как дубль, оставлена заглушкой «Снято при сведении: дублирует FR-…» (номер не переиспользуется, строки «Паритета» нет). FR с источником «новое (в ROADMAP CONTROL 2 отмечено ✅, в коде нет)» имеет «Паритет» «—» и в таблицу «Паритета» не входит.
- Свод после сведения: RTH — 10 FR (с источником «новое»: 1); ROO — 14 FR; FRQ — 23 FR (снято как дубли: 3); PRC — 19 FR (снято как дубли: 4); MIN — 12 FR; ANL — 13 FR; QLT — 9 FR (с источником «новое»: 2). Всего 100 номеров, из них снято как дубли 7; действующих FR — 93, среди них с источником «новое» 3. Строк «Паритета» — 90.

## 1. Критерий Рауса и Гурвица (RTH)

### FR-RTH-001: Вход в окно «Критерий Рауса» и порядок диалогов
- **Требование.** Программа должна по пункту «Критерий Рауса» открыть окно исследования. Если были открыты «Формирование» или «Просмотр», программа сначала закрывает их и применяет изменённые параметры. Затем, если в звеньях W, R, H, G есть буква A или B, она показывает окно «Значения» с диапазонами этих букв, и после «OK» считает таблицу. Если букв нет, диалога нет, а таблица состоит из одной клетки. Введённые диапазоны при каждом новом открытии окна сбрасываются.
- **Обоснование.** Порядок «закрыть ввод → диалог → счёт» виден пользователю. Какие буквы считаются «в линейной части», решает схема (область SCH): для Рауса важны только звенья W, R, H, G.
- **Источник.** 1.1; в Delphi: `RouthT.pas:397`, `RouthT.pas:365`; заметка: `notes/d_routh.md` §2.3
- **Приоритет.** обязательно
- **Проверка.** Сценарий UC (1.6) и осмотр окна; эталон: поведение Delphi 1.1 (оракул 1.4); допуск: качественная проверка.
- **Паритет.** P-RTH-001
- **Подэтап.** 6.4

### FR-RTH-002: Сетка значений A×B не больше 20×20
- **Требование.** Программа должна строить сетку значений букв по диапазонам «от», «до», «шаг». Число интервалов — `Round((до − от) / шаг)`, ограничено 0…19. Значит, по каждой букве не больше 20 значений, а таблица — не больше 20×20 клеток. Если |шаг| ≤ 1e-10 или буквы нет, значение одно. `Round` округляет половину к чётному. Строки таблицы — значения B, столбцы — значения A. Последнее значение может выйти за «до» из-за округления. Слишком малый шаг (результат деления больше 1e9 по модулю) не должен вызывать сбой: число интервалов ограничивается до округления.
- **Обоснование.** Предел 20 — размер таблицы оригинала. Узлы сетки в оригинале получаются накоплением (`A := A + шаг`), а при выборе клетки — по формуле `от + i·шаг`. Это даёт разницу в последних битах (причуда → 1.7); требование задаёт одно правило — `от + k·шаг`. Защита от огромного шага — исправление ошибки A10 из `audit.md`.
- **Источник.** 1.1; в Delphi: `RouthT.pas:88`; заметка: `notes/d_routh.md` §2.2
- **Приоритет.** обязательно
- **Проверка.** Тест ядра; эталон: оракул Delphi (1.4); допуск: по `docs/testing/tolerances.md` (1.3) для значений узлов.
- **Паритет.** P-RTH-002
- **Подэтап.** 5.3, 6.4

### FR-RTH-003: Раус в режиме совместимости 1.1: абсолютный порог 1e-5
- **Требование.** В режиме совместимости 1.1 программа должна считать в клетке число корней характеристического многочлена замкнутой системы в правой полуплоскости. Многочлен собирается для пары (A, B), запаздывание заменено дробью Паде выбранного порядка. Число корней — число смен знака в первом столбце таблицы Рауса. Если |свободный член| < 1e-5 или любой элемент первого столбца по модулю меньше 1e-5, в клетке «-» (нет данных). Нулевая строка и замена нуля на малое число не используются.
- **Обоснование.** Так считает 1.1. Порог абсолютный, поэтому результат зависит от масштаба коэффициентов (причуда → 1.7). Режим нужен для сверки с оригиналом; основной режим — FR-RTH-004.
- **Источник.** 1.1; в Delphi: `routh.pas:15`; заметка: `notes/d_routh.md` §2.1
- **Приоритет.** обязательно
- **Проверка.** Тест ядра; эталон: оракул Delphi (1.4); допуск: результат целый — совпадение точное.
- **Паритет.** P-RTH-003
- **Подэтап.** 5.3

### FR-RTH-004: Раус по умолчанию: относительный порог, нулевая строка, особые случаи
- **Требование.** Программа должна по умолчанию считать число корней в открытой правой полуплоскости так, чтобы масштаб многочлена и масштаб строк не менял результат. Для этого:
  - перед таблицей подставляется `p = 2^e·q` с целым e (точное умножение), чтобы отношение свободного члена к старшему было порядка 1;
  - каждая строка делится на свой наибольший по модулю элемент;
  - элемент таблицы считается нулём, если разность двух произведений не больше 1e-12 от суммы их модулей;
  - нулевая строка заменяется производной вспомогательного многочлена; число корней на мнимой оси находится по знакам ниже этой строки;
  - нулевой первый элемент при ненулевой строке снимается умножением многочлена на (p + c), c = 1; 2; 0,5; 3; …, а если не вышло, малым параметром ε = 1e-9 (результат помечается приближённым);
  - нулевые младшие коэффициенты — нулевые корни, они не входят в число правых, а считаются корнями на границе.
  Результат «нет данных» возможен только для нулевого многочлена. Если есть корни на мнимой оси и число правых корней меньше 10, клетка показывает число со звёздочкой.
- **Обоснование.** CONTROL 2, пункт 5.4. Абсолютный порог оригинала заменён относительным. Показ результата в строке состояния главного окна — FR-UI-007.
- **Источник.** К2; в Delphi: `RouthV2.pas:186`, `RouthT.pas:174`; заметка: `notes/d_routh.md` §2.1 (метод 1.1 для сравнения)
- **Приоритет.** обязательно
- **Проверка.** Тест ядра и property-based тест (умножение коэффициентов на число не меняет результат); эталон: число корней с Re > 0 по mpmath (1.5); допуск: целое число, звёздочка — при корне на оси в допуске корней.
- **Паритет.** P-RTH-004
- **Подэтап.** 5.3, 6.4

### FR-RTH-005: Определители Гурвица
- **Требование.** Программа должна вычислять определители Гурвица Δ1…Δn характеристического многочлена. Матрица Гурвица: `H[i][j] = A[2j − i]`, коэффициент вне 0…n равен нулю. Если старший коэффициент отрицателен, многочлен умножается на −1. Система устойчива по Гурвицу, если все Δk > 0. Определители должны быть доступны пользователю рядом с результатом Рауса; вид показа выбирает подэтап 6.4.
- **Обоснование.** CONTROL 2, пункт 5.4. В Delphi есть только функция расчёта, показа в окнах нет (ОВ-Б-2).
- **Источник.** новое (в ROADMAP CONTROL 2 отмечено ✅, в коде нет); в Delphi есть только функция расчёта `RouthV2.pas:279`, показа пользователю нет; заметка: `notes/d_routh.md` §1 (по коду CONTROL 2).
- **Приоритет.** желательно
- **Проверка.** Тест ядра; эталон: mpmath (1.5), определители по определению; допуск: по `docs/testing/tolerances.md` (1.3).
- **Паритет.** —
- **Подэтап.** 5.3, 6.4

### FR-RTH-006: Вид таблицы Рауса

В клетке стоит число неустойчивых корней, «-» или число со звёздочкой (FR-RTH-004). Над таблицей — пояснение, что в клетках число неустойчивых корней, а пропуск означает отсутствие данных. Для каждой использованной буквы показан диапазон в виде «от … до … с шагом …». Сетка подгоняется под размер окна (не меньше 5 столбцов и 4 строк); при развороте окна на весь экран видна сетка 21×21. Если букв нет, кнопка «OK» и строка выбора скрыты.

- **Подэтап.** 6.4

### FR-RTH-007: Выбор клетки таблицы и передача значений A, B другим окнам
- **Требование.** Программа должна при выборе клетки (щелчок или стрелки) показывать в строке под таблицей «(i) A = значение» и «(j) B = значение», где значение равно `от + i·шаг`. Число знаков после точки: 4 при |v| < 1, 3 при |v| < 10, иначе 2; хвостовые нули убираются. Кнопка «OK» (подсказка «Выбор значений») принимает значения как выбранные A и B и выдаёт сообщение «Вы выбрали значение» (или «значения», если букв две) с принятыми числами. Если клетка не выбрана, остаются прежние значения. Выбранные A и B дальше используются как текущие в окнах Найквиста, ЛАЧХ, АЧХ, таблицы корней, процесса и в анализе (FR-ANL-001).
- **Обоснование.** Переход значений между окнами — часть ROADMAP 1.1. Если в схеме буква только B, значение A в «OK» не копируется. Заметка допускала, что при одной букве B «OK» стирает A (ОВ-Б-3); требуется не стирать.
- **Источник.** 1.1; в Delphi: `RouthT.pas:303`, `RouthT.pas:496`; заметка: `notes/d_routh.md` §2.4
- **Приоритет.** обязательно
- **Проверка.** Сценарий UC (1.6): выбор клетки → «OK» → проверка значений в другом окне; эталон: поведение Delphi 1.1; допуск: строки значений совпадают.
- **Паритет.** P-RTH-007
- **Подэтап.** 6.4

## 2. Корни и корневой годограф (ROO)

### FR-ROO-001: Вход в окно «Корневой годограф» и диалог «Значения»
- **Требование.** Программа должна по пункту «Корневой годограф» открыть окно. Если были открыты «Формирование» или «Просмотр», они закрываются, изменения применяются. Если в схеме есть буква A или B, перед построением показывается окно «Значения»: «A от», «до», «шаг» и значение B (или только B). Введённые значения сбрасываются при каждом новом открытии окна. Если букв нет, строится один набор корней. Начальные границы осей: Re от −3 до 2, Im от −0,5 до 2.
- **Обоснование.** Порядок диалогов виден пользователю. Содержимое и проверки окна «Значения» — область INP (исполнитель А).
- **Источник.** 1.1; в Delphi: `Godgrf.pas:28`, `Godgrf.pas:150`; заметка: `notes/c_roots.md` §4
- **Приоритет.** обязательно
- **Проверка.** Сценарий UC (1.6) и осмотр окна; эталон: поведение Delphi 1.1 (оракул 1.4); допуск: качественная проверка.
- **Паритет.** P-ROO-001
- **Подэтап.** 6.4

### FR-ROO-002: Число значений A на годографе
- **Требование.** Программа должна брать значения `A_k = от + k·шаг`, k = 0…NA, где `NA = Round((до − от) / шаг)`, ограничено 0…10000. Если |шаг| ≤ 1e-10, значение одно. Слишком малый шаг не должен вызывать сбой: число интервалов ограничивается до округления.
- **Обоснование.** Предел 10000 — в коде. Справка оригинала обещает «не больше 200», разночтение записано в ОВ-Б-1. Оригинал получает A накоплением (причуда → 1.7); после счёта текущее A остаётся «последнее + шаг» (причуда → 1.7). Защита от огромного шага — ошибка A10 аудита.
- **Источник.** 1.1; в Delphi: `Godgrf.pas:150`; заметка: `notes/c_roots.md` §4
- **Приоритет.** обязательно
- **Проверка.** Тест ядра; эталон: оракул Delphi (1.4); допуск: по `docs/testing/tolerances.md` (1.3).
- **Паритет.** P-ROO-002
- **Подэтап.** 5.4, 6.4

### FR-ROO-003: Что строится на корневом годографе
- **Требование.** Программа должна для каждого значения A (B постоянно) находить корни характеристического многочлена замкнутой системы и наносить их точками на плоскость (Re p, Im p). ## 3. Частотные характеристики (FRQ)

### FR-FRQ-001: Порядок диалогов при открытии Найквиста, ЛАЧХ и АЧХ

- **Обоснование.** Порядок диалогов виден пользователю. Окно «Значения» — область INP (исполнитель А); «Разомкнуть систему» — два варианта «в точке h», «в точке x». Окно «Разомкнуть систему» (выбор, запоминание, OK) описано в FR-INP-017.

### FR-FRQ-002: Разомкнутая система и точка размыкания h или x
- **Требование.** Программа должна для Найквиста и ЛАЧХ строить частотную характеристику разомкнутой системы в выбранной точке. В точке h: `Wраз = H·R·W / (1 + R·G)`. В точке x: `Wраз = (H·W + G)·R`. Для АЧХ используется замкнутая система `Φ = R·W / (1 + R·G + R·W·H)`, f → y. Над графиком Найквиста и ЛАЧХ показывается «Размыкание в точке h» (или x); если подпись не помещается, короткая «Разм. в т. h». Смена точки размыкания пересчитывает график.
- **Обоснование.** Обозначения W, R, H, G, h, x — по [глоссарию](../../glossary.md). Многочлены собираются в области SCH; здесь только их использование. Окно выбора точки — FR-INP-017; определения точек h и x — FR-SCH-003. FR дополняют друг друга: здесь использование точки в частотных характеристиках.
- **Источник.** 1.1; в Delphi: `Clsyst.pas:432`, `Nyqst.pas:214`; заметка: `notes/e_freq.md` §3, §5.2
- **Приоритет.** обязательно
- **Проверка.** Тест ядра; эталон: оракул Delphi (1.4) и mpmath (1.5); допуск: по `docs/testing/tolerances.md` (1.3).
- **Паритет.** P-FRQ-002
- **Подэтап.** 5.5, 6.4

### FR-FRQ-003: Предобработка перед частотным графиком
- **Требование.** Программа должна перед построением Найквиста, ЛАЧХ и АЧХ собрать систему и при ошибке сборки закрыть окно (сообщение показывает сборка). Если все коэффициенты числителя (разомкнутого для Найквиста и ЛАЧХ, замкнутого для АЧХ) по модулю не больше 1e-10, программа сообщает «Отсутствует числитель передаточной функции» и закрывает окно. Затем она сокращает общий множитель p: пока свободные члены числителя и знаменателя оба меньше 1e-10 по модулю, порядок на копии снижается на 1. Исходная система при этом не меняется.
- **Обоснование.** Поведение 1.1. Оригинал уменьшал общий порядок системы до следующей сборки (побочное изменение, ошибка C6 аудита; причуда → 1.7); в CONTROL 2 порядок меняется только на снимке системы.

### FR-PRC-004: Структура процесса и сигналы схемы

Сравнения с порогами идут с допуском 1e-4 по |x|, знак x определяется с порогом 1e-10:
  - тип 2: зона нечувствительности a, насыщение b, наклон α за b; при `b ≤ a` — идеальное реле с зоной;
  - тип 3: двухпозиционное реле с гистерезисом: `|x| > a` включает c·sign x, иначе выход не меняется;
  - тип 4: при `|x| > a` выход c·sign x; при `|x| < a` выход меняет знак на обратный предыдущему, если предыдущий вход был по модулю больше a, иначе не меняется; между порогами выход не меняется;
  - тип 5: при `|x| > b` выход c·sign x; при `|x| < a` выход 0; между a и b выход c·sign x, если предыдущий выход не нулевой и a > 0, иначе не меняется (трёхпозиционное реле с гистерезисом);
  - тип 6: как тип 5, но при `|x|` между a и b выход определяется ещё и предыдущим входом: если предыдущий вход по модулю меньше a, выход c·sign x; если больше b, выход 0; иначе как у типа 5.
  Типы 8–12 CONTROL 2 — область SCH.
- **Обоснование.** Формулы 1.1 нужны для оракула. Условия типов 4–6 записаны по коду; полная таблица условий — в `notes/f_process.md` §4.2 и затем в `docs/math`. Определение типов и допустимость параметров — FR-SCH-022; типы 8–12 — FR-SCH-023.

### FR-MIN-005: Время регулирования по корням (три критерия)
- **Требование.** Программа должна для линейной системы при незаданном tрег находить для каждого варианта наибольшую Re корней характеристического многочлена замкнутой системы (с Паде) и далее:

## 7. Показатели качества (QLT)

### FR-QLT-001: Показатели переходного процесса
- **Требование.** Программа должна по сохранённой кривой y(t) процесса считать:
  - установившееся значение y∞ — среднее по последним 5 % точек; если |y∞| < 1e-9, показатели не определены, панель так и сообщает;
  - наибольшее значение yмакс и перерегулирование σ = (yмакс/y∞ − 1)·100 % (0, если выброса нет);
  - время первого максимума tм (вершина параболы по трём точкам) выше установившегося значения;
  - время нарастания tн между уровнями 10 % и 90 % от y∞ (линейная интерполяция); если 90 % не достигнуто, «не определено»;
  - время регулирования tр — момент последнего выхода кривой за полосу ±5 % или ±2 % от y∞ (линейная интерполяция до границы полосы); 0, если кривая всегда внутри полосы;
  - число колебаний N — число максимумов выше полосы до tр.
  Процесс считается неустановившимся, если последний выход за полосу приходится на последние 10 % точек или предыдущие 5 % точек отличаются от последних больше чем на 0,2 полосы; тогда вместо tр выводится «процесс не установился». Для кривой меньше 10 точек или с невозрастающим временем показатели не считаются («мало точек», «время не возрастает»).
- **Обоснование.** CONTROL 2, пункт 1.1. Студенты снимали эти величины курсором по пикселям; теперь они считаются по точкам кривой.
- **Источник.** К2; в Delphi: `Quality.pas:124`, `Quality.pas:619`; заметка: `CONTROL_src/ROADMAP.md` 1.1
- **Приоритет.** обязательно
- **Проверка.** Тест ядра на кривых с известными показателями (звенья 1-го и 2-го порядка); эталон: аналитические σ, tм, tр (mpmath, 1.5); допуск: по `docs/testing/tolerances.md` (1.3).
- **Паритет.** P-QLT-001
- **Подэтап.** 5.8
