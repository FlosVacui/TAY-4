# Критерии выбора стека и их веса (развилка Р-9)

| | |
|---|---|
| Версия | 1.0 от 03.11.2026, подэтап 1.0 |
| Статус | Утверждено пользователем 03.11.2026 ([Р-9](../DECISIONS.md#р-9-веса-критериев-стека)): рекомендуемый набор весов из раздела 3. Наборы раздела 4 — для проверки устойчивости в 2.1 |
| Где применяется | Подэтап 2.1 (сравнение вариантов A–M, черновик ADR-0001), пересчёт после замеров 2.3–2.4, решение Р-2 |
| Откуда требования | [SRS.md](SRS.md), раздел 4 |

## 1. Как идёт выбор
1. **Отсев.** Вариант, который не выполняет хотя бы одно обязательное условие О1–О5, выбывает. Причина записывается в ADR-0001.
2. **Оценка.** Каждый оставшийся вариант получает по каждому критерию К1–К14 оценку от 0 до 5. Источник каждой оценки — документация, замер или issue на GitHub — указывается ссылкой.
3. **Итог** = Σ (вес × оценка) / 5, максимум 100.
4. **Проверка устойчивости.** Итог считается ещё при двух других наборах весов (раздел 4). Если лидер меняется, это сообщается пользователю вместе с причиной.
5. **Финалисты.** Два лучших варианта проходят замеры ядра (2.3) и наброски (2.4). Оценки пересчитываются по замерам, затем пользователь решает Р-2.

**Шкала оценок:**
- **5** — выполняется штатными средствами; подтверждено замером или первоисточником;
- **4** — выполняется, есть мелкие оговорки;
- **3** — выполняется с заметной своей работой или с известными ограничениями;
- **2** — выполняется частично или обходным путём;
- **1** — только обходным путём с большим риском;
- **0** — не выполняется.

## 2. Обязательные условия (отсев)
| № | Условие | NFR |
|---|---|---|
| О1 | Официальная поддержка сборки и запуска на Windows 10 22H2 и 11 x64, Ubuntu 22.04/24.04 x64, macOS 13+ на Apple Silicon | PLT-001 |
| О2 | Полная работа без сети и без учётной записи | PLT-002 |
| О3 | Переносная сборка, которая запускается без прав администратора | PLT-003 |
| О4 | Можно работать бесплатно, без отчислений; свой код можно публиковать под Apache-2.0. Платные обновления LTS при бесплатных обычных выпусках (как у Qt) — не отсев, а оценка по К9 и К12 | MNT-002 |
| О5 | Ядро считает в IEEE 754 binary64, и FMA и «быструю математику» можно выключить. Без этого не получить одинаковых чисел на трёх ОС | ACC-001, ACC-002 |

## 3. Критерии и рекомендуемые веса
| № | Критерий | Что оценивается | Вес |
|---|---|---|---|
| К1 | Точность расчётов | Double-double и высокоточная арифметика, качество численных библиотек, контроль округлений, тестирование против mpmath | 12 |
| К2 | Одинаковые числа на всех ОС | Своя libm или libm без зависимостей от ОС, отсутствие неявного FMA, детерминизм при многопоточности | 5 |
| К3 | Скорость | Бюджеты NFR-PRF-001; перерисовка 100 000 точек; запуск; память | 10 |
| К4 | Интерфейс | Современный вид, понятность, HiDPI, темы, доступность, локализация, работа с клавиатуры | 12 |
| К5 | Диаграммы, печать, экспорт, формулы | Научные диаграммы с зумом и курсором; печать с предпросмотром; PDF/SVG/PNG, одинаковые на трёх ОС; вёрстка формул | 10 |
| К6 | Надёжность и тестируемость | Статическая типизация, безопасность памяти, модульные, property-based, мутационные, снимочные и e2e-тесты, фаззинг, линтеры | 10 |
| К7 | Установка на ПК кафедры | Переносная сборка Windows без прав администратора, размер, системные зависимости (WebView2, .NET, VC++), предупреждения SmartScreen | 8 |
| К8 | Linux и macOS | Одинаковое поведение и вид, сборка в CI на трёх ОС, Wayland и HiDPI на Linux | 5 |
| К9 | Зрелость и поддержка на 10 лет | Стабильная версия, политика LTS, активность, кто развивает, сколько проектов на стеке | 7 |
| К10 | Пригодность для всего ТАУ-3 | Общее ядро для 24 программ, библиотека, CLI, модуль Python | 7 |
| К11 | Удобство для ИИ-агентов | Насколько хорошо модели пишут код на стеке, скорость цикла «сборка — тест», понятность ошибок компилятора. Почти весь код пишут субагенты, поэтому это прямо влияет на число ошибок и сроки | 6 |
| К12 | Лицензии | Совместимость с Apache-2.0, нет ли модулей под GPL (например, Qt Charts), условия LGPL | 4 |
| К13 | Веб-версия | Можно ли запустить ядро и интерфейс в браузере (WASM) | 2 |
| К14 | Подпись и сервисы из России | Нужны ли платные сервисы, можно ли их оплатить; что будет без подписи (Р-7) | 2 |
| | **Сумма** | | **100** |

**Почему так:**
- **Точность (К1)** весит много, но стеки по ней различаются слабо: почти все считают в IEEE double. Главное для точности задаёт условие О5 и мат. спецификации, а К1 различает только инструменты (double-double, библиотеки, mpmath в тестах).
- **Интерфейс (К4) равен точности.** Программу будут показывать на кафедре, и понятность интерфейса пользователь назвал главным наряду с правильностью расчётов.
- **Скорость (К3)** важна, но бюджеты NFR-PRF-001 малы для любого компилируемого ядра. К3 в основном различает перерисовку больших диаграмм и время запуска.
- **Веб-версия (К13) и подпись (К14)** весят мало: веб-версия по рекомендации идёт в 1.x (Р-3), а подпись заменяют инструкция и переносные сборки (Р-7).
- **Простота разработки** отдельным критерием не стоит (решение пользователя). Учитывается только удобство для ИИ-агентов (К11) — от него зависит число ошибок.

## 5. Что нужно проверить в 2.1 по первоисточникам
- Поддержка Windows 10 у каждого стека после окончания её поддержки Microsoft (14.10.2025), в том числе WebView2 для Tauri.
- Есть ли WebView2 в чистой Windows 10 22H2 без интернета и можно ли положить его в переносную сборку (Fixed Version).
- Лицензии: Qt 6 (LGPL и модули под GPL), Slint (условия бесплатной лицензии), ScottPlot, ImPlot и другие.
- Размер переносной сборки и время запуска у каждого варианта.
- Запуск неподписанной сборки на macOS (Gatekeeper) и AppImage на Ubuntu 22.04/24.04 (нужен ли `libfuse2`).
- Как каждый стек выключает FMA и «быструю математику» (например, `-ffp-contract=off` в GCC, где по умолчанию FMA разрешён).
