# Регресс по аудиту оригинала (TC-AUD)

Подэтап 1.1, исполнитель В. Формат записей — [шаблон](../../templates/test-case.md). Источник — заметка `work/control/notes/audit.md` (аудит копии CONTROL, 21–23.10.2026): разделы A (ошибки, ломающие работу), B (дыры во вводе, файлах и окружении), C (неоптимальный код), D (сборка и инструменты) и «Повторный проход». Требования — в `docs/requirements/fr/output-shell.md` и в файлах других исполнителей той же папки.

## Соглашения

- **Номера.** `TC-AUD-<NNN>` идут по порядку; в названии стоит ID из аудита (A0…A10, B1…B7, C…, D…). Латинские буквы в ID — как в аудите.
- **Что проверяется.** Для каждой ошибки записано *правильное* поведение ТАУ-4 (после исправления), а не поведение оригинала. Поведение оригинала даёт эталон «до» и описано в первой строке «Ожидаемого результата».
- **Данные.** Варианты с именами `fixtures/audit/<имя>.json` создаёт подэтап 1.4; здесь они описаны словами. Для вариантов в старом формате указано `.vrt`.
- **FR других исполнителей.** Ссылки на FR исполнителей А и Б уточнены при сведении (исполнитель Г); заглушек вместо ID не осталось. FR, снятые как дубли, в ссылках заменены на FR-владельцев.
- **Автотест.** Имена `tests/audit/...` — предложение; стек и каталог тестов определит этап 2/4. До появления кода поле означает «будет создан».
- **ОС.** Все три ОС, если не указано иное. Шаги, зависящие от Windows (VirtualStore, WinHelp), помечены.
- **Метки повторного прохода.** В разделе «Повторный проход (2026-10-22)» заметки `audit.md` нет ID, там маркированный список из пяти пунктов. Метки P1…P4 — условные, даны составителем по порядку пунктов списка: P1 — неинициализированные значения в шаге РК4 и в таблице частот; P2 — пункт «Таблица корней» в окне Рауса; P3 — щелчок ниже последней строки таблицы корней; P4 — Ctrl+C в окне сообщения. P5 — не из `audit.md`: источник — `notes/README.md`, «Решения», п. 3 (зависание после ошибки при рисовании: отметки частот и кривая Попова).
- **Не подтверждено запуском.** A7, A8 и C6 найдены чтением кода (`audit.md`: «по коду»). Для них в «Ожидаемом результате» написано, что именно проверить, и вопрос внесён в `ОВ-В-21` файла `output-shell.md`.

### TC-AUD-001: A0 — ошибки плавающей точки не проходят молча
- **Проверяет.** NFR-ACC-004, FR-UI-015, FR-UI-014 (каталог сообщений); строки «Паритета»: P-UI-019, P-UI-018.
- **Вид.** сценарный (UC) и автотест; сверка файлов на NaN и INF.
- **Исходные данные.** Два варианта: `fixtures/audit/a0-g-empty.json` (звено G типа 12 с пустыми параметрами, остальные звенья по умолчанию, H = 1, f = 1) и `fixtures/audit/a0-neg-step.json` (W = 1/(p+1), частоты от 3 до 0,2 с шагом −0,2).
- **Шаги.**
  1. Открыть `a0-g-empty` и вызвать Найквиста, ЛАЧХ, АЧХ и таблицу корней.
  2. Открыть `a0-neg-step`, вызвать Найквиста, в окне «Частоты» задать указанный ряд.
  3. После каждого шага записать таблицу «В файл» (если она открывается) и просмотреть файл.
  4. В командной строке выполнить `/calc a0-g-empty.json /bode b.csv /step s.csv`, проверить код возврата и файлы.
- **Ожидаемый результат.** Оригинал: «Invalid floating point operation.» и блокировка окон; копия без маски выдавала неверное сообщение «Отсутствует числитель передаточной функции». ТАУ-4: на шаге 1 одно сообщение «Неверно задан элемент системы G»; на шаге 2 отметки на тех же частотах (ряд переворачивается) или понятное сообщение; нигде нет NaN, INF, «NAN», «INF» в окнах и файлах; окна не блокируются; командная строка возвращает код 3 с причиной в журнале; эталон: описание поведения по аудиту A0, A9; допуск: точное совпадение текста сообщения, отсутствие нечисловых значений.
- **Автотест.** `tests/audit/test_a0_nan_free` (будет создан).
- **ОС.** Все.

### TC-AUD-004: A3 — запаздывание около 1024 шагов буфера
- **Проверяет.** FR-PRC-007 (процесс, режим 1.1), FR-PRC-008 (буфер по потребности), FR-MIN-009 (поиск минимума), FR-SCH-013, FR-UI-014 (сообщение «Запаздывание велико…»); строки «Паритета»: P-PRC-007, P-PRC-008, P-MIN-009, P-SCH-013, P-UI-018.
- **Вид.** разностный против оракула и сценарный (UC).
- **Исходные данные.** `fixtures/audit/a3-delay.json`: W = 0,1·e^(−τp)/(10p+1) с τ = A, R = H = 1; «Шаг счёта» 0,01; окно по времени 10 с (внутренний шаг 0,005). Значения τ: 5,0; 5,11; 5,12; 6,0.
- **Шаги.**
  1. Для каждого τ вызвать «Процесс регулирования» (A = τ).
  2. Для τ = 5,12 вызвать «Поиск минимума» с диапазоном A от 5,12 до 5,12 (одно значение).
  3. Сравнить результаты для τ = 5,0 и 5,11 с оракулом.
  4. Повторить шаги 1 и 2 в режиме совместимости с 1.1 (FR-PRC-007), затем в основном режиме (FR-PRC-008) и сравнить результаты для τ = 5,12 и 6,0 с оракулом.
- **Ожидаемый результат.** Оригинал и копия до исправления: для τ = 5,12 «Range check error.» и в процессе, и в поиске минимума. Режим совместимости с 1.1 (FR-PRC-007, FR-MIN-009): для τ = 5,12 и 6,0 ровно одно сообщение «Запаздывание велико для выбранного масштаба» (MSG-014), без «Range check error»; поиск минимума прерывается с записью в таблицу. Основной режим (FR-PRC-008): для τ = 5,12 и 6,0 сообщения нет, счёт идёт до конца, кривая совпадает с оракулом (предел буфера около 2 000 000 шагов); эталон: оракул Delphi (1.4) и mpmath (1.5); допуск: по `docs/testing/tolerances.md` (1.3), текст сообщения и число сообщений — точное совпадение.
